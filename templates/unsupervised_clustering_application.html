K-Means Clustering — Application



Problem Context

Shopping malls want to understand their customers beyond a single average profile, so they can design marketing strategies that actually match how different groups of shoppers behave. The phenomenon analyzed here is customer segmentation. Each row in the dataset represents one mall customer, described by their annual income and their spending score. Unlike the classification models used elsewhere in this project, clustering does not rely on a labeled target variable. Instead, the algorithm discovers natural groupings in the data on its own, based purely on how similar customers are to one another. The value the model attempts to discover is the group, or cluster, each customer naturally belongs to.

Annual Income and Spending Score were chosen because together they capture both a customer's purchasing power and their actual buying behavior. Income alone only shows what a customer could spend, while Spending Score alone only shows how much they do spend, without context. Combining both variables reveals meaningful patterns, such as customers with high income but low spending, or customers with modest income but high spending, that a single variable could never expose on its own.

Data Preprocessing

Before training, the raw dataset was checked for missing values. {{ dataset_info.n_dropped }} records containing null values were removed, leaving {{ dataset_info.n_records }} clean records for clustering. Because Annual Income and Spending Score are measured on very different scales (income in thousands of dollars, spending score from 1 to 100), both variables were standardized using scikit-learn's StandardScaler before training. This step is essential for K-Means, since the algorithm groups points based on distance, and a variable with a larger numeric range would otherwise dominate the distance calculation and distort the clusters.

K-Means Model Configuration

A KMeans model from scikit-learn was trained on the scaled Annual Income and Spending Score values, following this pipeline:

CSV Dataset → Pandas → Drop Nulls → Feature Scaling → K-Means Training → Cluster Assignment → Evaluation → Visualization

The model is configured as KMeans(n_clusters={{ dataset_info.n_clusters }}, random_state={{ dataset_info.random_state }}, n_init={{ dataset_info.n_init }}):

  • n_clusters = {{ dataset_info.n_clusters }}: the number of customer groups, selected with the elbow method shown below.
  • random_state = {{ dataset_info.random_state }}: fixes the random initialization, so the same clusters are obtained every time the application starts.
  • n_init = {{ dataset_info.n_init }}: the algorithm runs {{ dataset_info.n_init }} times with different initial centroids (k-means++) and keeps the solution with the lowest inertia, reducing the risk of a poor local solution.

To select K, the model was trained with K from 2 to 6, comparing the inertia (within-cluster sum of squares, used in the elbow method) and the silhouette score:

The inertia decreases sharply up to K = 4, and the improvement becomes small afterwards, which places the elbow of the curve at K = 4. Although K = 2 and K = 3 obtain higher silhouette scores, with K = 3 the largest cluster mixes the low-income, high-spending customers with the average customers, two profiles that require different marketing actions. K = 4 separates them, so it was selected as a balance between compactness, separation, and the usefulness of the segments for the business.

Model Evaluation — Silhouette Score

The clustering was evaluated using the silhouette score, which measures how well each customer fits within its assigned cluster compared to the next closest cluster. The score ranges from -1 to 1: values close to 1 indicate dense, well-separated clusters, values near 0 indicate overlapping clusters, and negative values indicate customers that may have been assigned to the wrong cluster. The model achieved a silhouette score of {{ dataset_info.silhouette_score | round(4) }}, which indicates {% if dataset_info.silhouette_score >= 0.5 %} strong, well-separated clustering, meaning customers within each group are clearly more similar to one another than to customers in other groups. This gives confidence that the cluster profiles described above reflect real, distinct customer segments. {% elif dataset_info.silhouette_score >= 0.25 %} a reasonable, moderate degree of separation between clusters. Some overlap likely exists near the cluster boundaries, but the overall grouping is still meaningful enough to support the customer profiles described above. {% else %} weak separation between clusters, suggesting significant overlap. The general groupings can still offer some useful signal, but the boundaries between customer segments should be interpreted with caution. {% endif %}
